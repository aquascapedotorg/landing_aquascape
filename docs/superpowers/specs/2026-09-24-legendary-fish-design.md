# Desain: Ikan Legendaris Emas (Ultra-Rare, Persisten di DB)

Tanggal: 2026-09-24
Status: Disetujui untuk implementasi (menunggu review spec)
Menggantikan draft sebelumnya (deterministik harian). Membangun di atas fitur
communal fish + streak/leaderboard (mode Supabase).

## 1. Tujuan

Saat sebuah ikan dikirim (via webhook → `communal_fishes`), ada peluang **sangat
kecil (~1%)** peserta itu menjadi **Legendaris**. Kemenangan **tersimpan permanen di
DB** (ter-record). Ikan legendaris di-render sebagai **Koi emas mewah** yang bersinar
(glow berdenyut + partikel kilau + jejak berkilau), dengan **banner megah** di Zen
mode. Tidak harus ada legendaris setiap hari. Fitur **hanya aktif di mode Supabase**.

## 2. Prinsip Keandalan (server-authoritative & idempoten)

Kunci desain: lemparan dadu terjadi **sekali per ikan**, apa pun jumlah pengunjung.

- App banyak pengunjung memanggil RPC `roll_legendary(name)` saat mendeteksi ikan baru.
- RPC harus **idempoten**: tiap baris ikan hanya boleh di-roll **sekali** seumur hidup.
  Server menandai "sudah di-roll" agar pemanggilan berulang (dari banyak browser /
  refresh) TIDAK melempar dadu lagi. Ini menjaga peluang efektif tetap ~1%.
- Server yang memutuskan (random di dalam RPC), bukan client — client tidak bisa
  memaksa kemenangan.

## 3. Skema DB (Supabase)

### 3a. Kolom penanda "sudah di-roll" pada communal_fishes

```sql
alter table public.communal_fishes
  add column if not exists legendary_rolled boolean not null default false;
```

Menandai bahwa baris ikan ini sudah pernah dilempar dadu (menang atau kalah), sehingga
roll berikutnya di-skip (idempoten).

### 3b. Tabel histori legendaris

```sql
create table if not exists public.legendary_fish (
  id           bigint generated by default as identity primary key,
  name         text not null,
  species      text,
  entry_date   date not null default current_date,
  won_at       timestamptz not null default now()
);

alter table public.legendary_fish enable row level security;
drop policy if exists "Allow public read access" on public.legendary_fish;
create policy "Allow public read access" on public.legendary_fish for select using (true);
-- No public insert/update/delete: writes happen ONLY via the SECURITY DEFINER RPC.

alter publication supabase_realtime add table public.legendary_fish; -- (guarded, see streak.sql pattern)
```

Read publik (agar client bisa menampilkan legenda); tulis hanya lewat RPC.

### 3c. RPC roll_legendary (ultra-rare, idempoten, atomik)

```sql
create or replace function public.roll_legendary(p_name text)
returns boolean            -- true if this call made them legendary
language plpgsql security definer as $$
declare
  v_name text := btrim(regexp_replace(coalesce(p_name,''), '\s+', ' ', 'g'));
  v_row  public.communal_fishes;
  v_win  boolean := false;
begin
  if char_length(v_name) < 1 then return false; end if;

  -- Find today's most recent unrolled row for this participant, lock it.
  select * into v_row
  from public.communal_fishes
  where btrim(regexp_replace(name,'\s+',' ','g')) = v_name
    and entry_date = current_date
    and legendary_rolled = false
  order by created_at desc
  limit 1
  for update skip locked;

  if not found then
    return false; -- already rolled (idempotent) or no row today
  end if;

  -- Mark as rolled so no one can re-roll this fish.
  update public.communal_fishes set legendary_rolled = true where id = v_row.id;

  -- The ultra-rare dice (1%).
  if random() < 0.01 then
    v_win := true;
    insert into public.legendary_fish (name, species, entry_date)
    values (v_name, v_row.species, current_date);
  end if;

  return v_win;
end;
$$;

grant execute on function public.roll_legendary(text) to anon;
```

Catatan: `for update skip locked` + cek `legendary_rolled` membuat roll aman terhadap
banyak pemanggil bersamaan — hanya satu yang berhasil mengklaim & melempar dadu; sisanya
`not found` → `false`.

Rarity `0.01` = 1% (bisa disesuaikan di satu tempat).

## 4. Layanan Client: legendaryService.ts

Tanggung jawab: (a) memicu roll untuk ikan baru, (b) menyimpan daftar nama legendaris
hari ini untuk render/banner.

- `initLegendaryService()` — Supabase-only, idempoten. Buat client Supabase (atau pakai
  yang ada), lalu:
  - **Fetch legendaris hari ini** dari `legendary_fish` (`entry_date = today`) → simpan
    `Set<string>` nama legendaris.
  - **Subscribe realtime** `legendary_fish` INSERT → tambah ke set + emit event.
  - Recompute saat hari berganti diabaikan (page reload menyegarkan).
- `rollForFish(name)` — panggil RPC `roll_legendary(name)`. Dipanggil oleh alur "ikan
  baru terdeteksi" (lihat §5). Fire-and-forget; kemenangan akan datang balik lewat
  realtime `legendary_fish` sehingga semua klien konsisten.
- `getLegendaryNames(): Set<string>` — untuk canvas tagging.
- `getTodayLegendaryList(): { name: string; species?: string }[]` — untuk banner.
- `isLegendary(name): boolean` — helper (pakai normalizeName).
- Event: pakai `aquascapeEvents` — tambah `onLegendaryUpdated`/`notifyLegendaryUpdated`.

## 5. Memicu Roll untuk Ikan Baru

Ikan baru terdeteksi di alur communal yang sudah ada (realtime INSERT + polling di
`subscribeToSupabaseFish` / `loadFishNamesCatalog`). Pada setiap ikan baru yang
di-spawn (bukan yang sudah ada saat load awal), panggil `legendaryService.rollForFish(name)`.

- Untuk ikan yang sudah ada saat halaman dibuka (initial fetch), JANGAN roll di client
  (mereka sudah pernah di-roll saat pertama dikirim). RPC tetap idempoten sebagai
  pengaman ganda (`legendary_rolled` sudah true).
- Webhook Anda TIDAK berubah (tetap kirim name+species). Roll dipicu app.

## 6. Menandai & Merender (canvas)

- `FishParticle.isLegendary?: boolean`.
- `tagLegendary(list)`: set `isLegendary = isCommunal && getLegendaryNames().has(normalizeName(name))`.
  Dipanggil di titik roster berubah + saat `onLegendaryUpdated`.
- Render **Koi emas** menimpa render jenis asli (cabang pertama di chain species):
  badan koi gradasi emas (highlight `#fff3b0`, body `#f5c542`, shadow `#b8860b`), sirip
  & ekor mengalir (berayun pakai tailWag), bercak koi lembut, mata; ukuran `size*1.15`.
- Efek (world coords, di belakang/sekitar): **glow emas berdenyut**, **partikel kilau
  (sparkle)**, **jejak berkilau (trail)** (ref `Map<id,{x,y}[]>`, ~14 titik).

## 7. Nametag Emas

`drawFishNametag`: bila `fish.isLegendary`, pill & teks emas + selalu tampil (kecuali
clean mode). (Ikon bintang opsional via path — boleh dilewati untuk kesederhanaan.)

## 8. Banner Zen

Bila mode Supabase & ada legendaris hari ini: banner megah (atas-tengah, di bawah
header, pointer-events none). Bila >1 legendaris hari itu, tampilkan yang terbaru (atau
rotasi sederhana — cukup terbaru untuk lingkup ini). Teks:
- Utama: **"{Name} — Shining Gold, Chosen Today"**
- Sub: **"Aquascape Legend"**
- Warna emas + sedikit glow; ikon `Sparkles` (lucide). Hidden saat clean mode.
- Update reaktif via `onLegendaryUpdated`.

## 9. Aktivasi

- Semua hanya bila `isSupabaseModeActive()`.
- `initLegendaryService()` dipanggil di cabang sukses Supabase (`fishCatalog.ts`),
  setelah streak service.
- Mode lokal: tidak ada roll, tidak ada koi/banner.

## 11. Edge Case

- Banyak pengunjung online → RPC idempoten memastikan tiap ikan di-roll sekali (peluang
  tetap ~1%).
- Ikan lama saat load → tidak di-roll ulang (sudah `legendary_rolled=true`); pengaman RPC.
- Legendaris belum ter-spawn sebagai partikel → koi muncul begitu partikel ada.
- Nama varian spasi → `normalizeName` di RPC (regexp) & client konsisten.
- Tabel/RPC belum dibuat di DB → app degrade mulus: `rollForFish` gagal diam-diam, fetch
  `legendary_fish` 404 → set kosong, tidak ada koi/banner, tidak crash.
- Clean mode → banner & nametag emas tersembunyi; koi + glow tetap (bagian kanvas).
- 0 legendaris hari itu → tidak ada koi/banner (normal, karena ultra-rare).

## 12. Testing

- `legendaryService` (unit, mock RPC/fetch minimal): getters default kosong; set/reset
  test hooks; `isLegendary` pakai normalizeName; rollForFish tidak crash tanpa client.
- SQL/RPC: diuji manual (idempotensi — panggil 2× untuk 1 ikan hanya menandai sekali;
  peluang menang ~1%). Bisa uji cepat dengan menaikkan rarity sementara.
- Verifikasi manual browser: paksa satu kemenangan (jalankan RPC dengan rarity 100%
  sementara, atau insert manual ke legendary_fish) → koi emas + glow/sparkle/trail +
  banner muncul; nonaktif di mode lokal; hidden di clean mode.

## 13. Di Luar Lingkup (YAGNI)

- Halaman arsip legenda / galeri histori.
- Hadiah/bonus untuk pemenang.
- Roll terjadwal harian (kita pakai per-kiriman).
- Anti-abuse tambahan di luar idempotensi RPC.
- Animasi transisi khusus saat seseorang "menjadi" legend.
